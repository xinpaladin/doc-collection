### 第 5 章　监控业务
#### 5.1 业务KPI(有点迷惑？这部分是监控需要做的还是业务部门报表？)
关键绩效指标（KPI）是一种衡量公司认为对业务健康发展非常重要的各个方面的整体表现如何的指标
部分KPI任务：
- 客户流失
- 活跃用户数
- 月度经常性收入
- 每位客户收入
- 付费客户数
- 净推荐值
- 客户终生价值（LTV）
- 每位客户成本
- ...

#### 5.2　两个真实的案例

##### 5.2.1　Yelp（类大众点评）
业务 KPI 的清单：
- 执行的检索数
- 发布的评论
- 注册用户
- 申请的商家页面
- 活跃用户
- 活跃商家
- 已购买的广告
- 发布的评论回应

跟踪这些指标的另一个连带作用是你将快速看到后端问题对用户产生的影响

##### 5.2.2　Reddit(社交平台)
衡量核心功能可能是这样的：
- 当前在线的用户
- 用户登录
- 提交的评论
- 提交的帖子
- 发起的投票
- 发送的私信
- 已售 Gold 账号
- 已售广告

#### 5.3　将业务KPI与技术指标绑定

|业务KPI|技术指标|
|--|--|
|当前在线的用户|当前在线的用户|
|用户登录|用户登录失败，登录延迟|
|提交的评论|提交评论失败，提交延迟|
|提交的帖子|提交帖子失败，提交延迟|
|发起的投票|投票失败，投票延迟|

> 扩展：由用户登录 -> 1. 请求延时；2.成功率；3.近n分钟的失败次数；...

新指标在比以前更细粒度的层面上回答了应用程序是否工作的问题

#### 5.4　应用程序没有提供这些指标
要了解应用程序和基础设施的性能，必须事前就对其进行设计。
如果应用程序没有公开所需要的指标，请亲自动手修改应用程序

### 第 8 章　服务器监控

#### 8.1　标准操作系统指标
反对痴迷于标准操作系统指标（CPU、内存、负载、网络和磁盘），重点在于讨论它们的含义以及如何使用

##### 8.1.1　CPU
指标数据源于 /proc/stat, `top`
```
Tasks:  74 total,   1 running,  73 sleeping,   0 stopped,   0 zombie
%Cpu(s):  0.0 us,  0.1 sy,  0.0 ni, 99.8 id,  0.0 wa,  0.0 hi,  0.0 si,  0.0 st
MiB Mem :   7776.4 total,   4968.8 free,   2206.4 used,    601.2 buff/cache
MiB Swap:   2048.0 total,   2048.0 free,      0.0 used.   5272.5 avail Mem
```
用户（us）、系统（sy）、改变过优先级的进程（ni）、硬件中断（hi）和软件中断（si）求和。iowait 进程（wa）和被虚拟化偷走的时间（st）

##### 8.1.2　内存
已使用百分比和空闲百分比是最主要的
多数工具基于 /proc/meminfo 报告的值来报告内存指标

##### 8.1.3　网络
Linux 中的信息基本上来自 /proc/net/dev

##### 8.1.4　磁盘
同一个来源：/proc/diskstats

##### 8.1.5　负载
负载度量的是有多少进程在等待由 CPU 提供服务
查看这个指标的最常见方法是使用 uptime 命令（它从 /proc/loadavg 中提取数据
具有一个 CPU 核心的系统上显示负载为 1.0，意味着正好有一个进程在等待。
问题是负载指标并不对应系统性能。服务器的负载指标很高，但性能良好，这种现象很常见。
唯一的例外是负载是一个相当不错的**代理指标**。也就是说，不正常的负载指标常常预示着存在其他问题.

#### 8.2　SSL证书
监控方式：
- 许多域注册机构和证书颁发机构（CA）能够监控 SSL 证书并在到期前通知你（如果你是通过它们来购买的证书）
- 如果 SSL 证书在外部使用，使用外部站点监控工具 （Prometheus） 

#### 8.3　SNMP
停止在服务器上使用 SNMP

#### 8.4　Web服务器
黄金指标：每秒请求数(req/sec)

#### 8.5　数据库服务器
指标：
- 连接数
- 每秒查询数（qps）
- 慢查询，被记录在日志文件中，包括执行时间、执行次数和查询本身
- 监控复制延迟

#### 8.6　负载均衡器
负载均衡器通过健康检查来确定后端服务器的状态

#### 8.7　消息队列
监控一个队列主要涉及两件事：
- 队列长度
- 消费率

#### 8.8　缓存
缓存的主要指标是
- 逐出项的数量和 高逐出率是缓存过小的信号，会导致过多的项目被逐出以便为新项目腾出空间
- 命中/未命中比例（有时候称为缓存命中率）

#### 8.9　DNS

运行着自己的 DNS，有两件事需要关注：
- 区域传输数
- 每秒查询数。

#### 8.10　NTP
确实运行着 NTP 服务器，你还需要关注对等点和服务器之间的偏移量（ntpdate 提供相关信息）

#### 8.11　其他企业基础设施

##### 8.11.1　DHCP
- DHCP 服务器发放租赁
- DHCP 池是否有足够的租赁容量

##### 8.11.2　SMTP
- 出站邮件队列反映了有多少邮件正在等待被发送出去。
- 发送和接收邮件的总量

##### 8.12　监控定时任务
失能开关：默认执行某个动作，除非有什么东西告诉它不要这样做。
```shell
#!/bin/sh
# 时间，单位是分钟
TIME_LIMIT=$((60*60))
# 用于更新最后一次接触的状态文件
STATE_FILE=deadman.dat
# 状态文件的最后访问时间（纪元时间）
last_touch=$(stat -c %Y $STATE_FILE)
# 当前时间（纪元时间）
current_time=$(date +%s)
# 距离启动开关还有多少时间
timeleft=$((current_time - last_touch))
if [ $timeleft -gt $TIME_LIMIT ]; then
  echo "Dead man's switch activated: job failed!"
fi
```
代码放入独立的 cron 作业中，每分钟运行一次，然后将之前的备份作业修改成这样
```shell
run-backup.sh && touch deadman.dat
```

### 第 9 章　网络监控
> 这章主要讲使用snmp监控网络设备。这部分与设备厂商高度有关。
#### 9.1　SNMP之痛
监控网络性能的最大挑战就是你必须使用 SNMP

##### 9.1.1　什么是SNMP
古老的协议，它被设计用于监控和管理广泛的事物，通常在服务器和网络设备上使用

##### 9.1.2　它的工作原理是什么
SNMP 是一种基于 UDP 的协议，使用端口 161 和 162。Polling（轮询）出现在 161 端口（设备入站）上，而 Trap（自陷）使用 162 端口（设备出站）

##### 9.1.3　关于安全的一点建议
SNMP 是一种先天不安全的协议
保护 SNMP 的最好方式是将安全构建于基础设施中

##### 9.1.4　如何使用SNMP
内容简单，网上到处都有

##### 9.1.5　接口指标
网络性能可以总结为一些关键因素：
- 带宽 
理论上可以同时通过连接推送的最大信息量,一般用位/秒来表示，通常是兆位/秒（Mbps）或千兆位/秒（Gbps）
- 吞吐率 观察到的网络链接的性能，也用位/秒来表示
- 延迟
- 错误 包括诸如 Rx/Tx 错误、丢弃、CRC 错误、溢出、载波错误、重置和冲突等指标
- 抖动 一个指标与其通常测量值的偏差
